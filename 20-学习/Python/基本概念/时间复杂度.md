# Python 时间复杂度完整概念解析

---

## 1. 基础定义

时间复杂度是评估算法运行效率的理论指标，描述数据量 `n` 不断增大时，程序运算次数的增长趋势。

- **不统计**代码真实运行毫秒数（受电脑性能、系统影响）；
- **只关注**数据规模变大后的性能变化规律；
- 统一使用 **大 O 符号（Big-O Notation）** 标记。

### 简化规则

只保留增长最快的最高次项，忽略常数、低次项、系数：

| 运算次数 | 复杂度 |
|---------|--------|
| `5n + 200` | **O(n)** |
| `3n² + 10n + 5` | **O(n²)** |

---

## 2. 常见复杂度等级（由快至慢）

| 复杂度标记 | 名称 | 特征说明 | Python 代码示例 |
|-----------|------|---------|----------------|
| **O(1)** | 常数阶 | 无论数据多少，执行次数固定，性能最优 | 无循环，简单赋值、打印 |
| **O(log n)** | 对数阶 | 数据规模翻倍时，运算次数通常只增加常数级 | 二分查找、循环每次把范围折半 |
| **O(n)** | 线性阶 | 数据量多大，循环执行多少次 | 单层 `for` 循环遍历列表 |
| **O(n log n)** | 线性对数阶 | 主流高效排序算法复杂度 | Python 内置 `sorted()`、`list.sort()` |
| **O(n²)** | 平方阶 | 两层循环规模都随 n 增长时，数据量大后速度会明显下降 | `for` 循环内嵌套一层规模同样增长的 `for` 循环 |
| **O(2ⁿ) / O(n!)** | 指数 / 阶乘阶 | 递归穷举，数据稍大直接卡死，不推荐 | 全排列、暴力枚举递归 |

---

## 3. 时间复杂度和实际运行时间的区别
* 时间复杂度
	* 预判海量数据下的性能上限，用于算法选型优化
	* 不反映具体毫秒数
* 装饰器计时 
	* 输出当前小数据的真实运行耗时
	* 只能反映当下环境速度，无法预测大数据场景

---

## 4. 最好、最坏和平均复杂度

同一个算法可能因为输入不同而表现出不同复杂度：

- 最好情况：最理想输入下的复杂度。
- 最坏情况：最不利输入下的复杂度。
- 平均情况：对所有可能输入取平均后的复杂度。

例如快速排序平均复杂度是 `O(n log n)`，最坏情况下可能退化到 `O(n²)`。

## 5. 空间复杂度

空间复杂度描述算法额外占用的内存随数据规模增长的趋势，同样使用大 O 表示。

```python
# 额外空间 O(1)：只使用固定数量的变量
def sum_list(numbers):
    total = 0
    for number in numbers:
        total += number
    return total

# 额外空间 O(n)：创建与输入规模相同的列表
def copy_list(numbers):
    return [number for number in numbers]
```

## 6. 递归算法的复杂度

递归算法不仅要看每层做了多少工作，还要看递归深度和每层产生的调用数量。

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)
```

上面这个阶乘函数每层只调用一次自身，递归深度为 `n`，因此时间复杂度、调用栈空间复杂度都是 `O(n)`。

## 7. 分析步骤

1. 找到决定运行次数的主要变量。
2. 判断循环是否随数据规模增长。
3. 计算每层循环的工作量。
4. 保留增长最快的项，忽略常数和低次项。
5. 区分最好、最坏和平均情况，并单独考虑额外空间。
